Building the ship's hub in Blender

The hub is the hangar deck the squad walks around between missions. It's the ONLY level we build by hand in Blender. It lives at content/modules/hub/hangar_deck.gltf, and its source goes in content/raw/modules/hub/hangar_deck.blend.

So what about the rooms in procedural levels? Those aren't built in Blender at all. Each one (the station's insertion bay, corridors and stairwell included) is a room archetype in content/defs/procgen/archetypes.json: a shape, its roles, a style and a furnishing, built from a seed. Its set pieces (a terminal, a reactor's core, the mess's counter) are props placed by its furnishing's rules. Studio's Levels > Archetypes tab edits them and shows each one built. See adding-content.md and the Studio reference.

Setup (once)

  1. Install Blender 4.2 or newer.
  2. In Blender, go to Edit > Preferences > Add-ons. Choose Install from Disk (in the drop-down at the top right), pick tools/blender/lastfleet_hub.py, and tick Last Fleet Ship's Hub.
  3. In the 3D view, press N to open the sidebar. You'll find the tools on the Last Fleet tab, in the Ship's hub panel.

Building the deck

The file you start from is the old deck that code built from boxes, exported box for box (tools/greybox/generate_hub.py). Replace it however you like, just don't run that script again over your work!

Here's the flow:

  1. Open it. Start an empty file and use File > Import > glTF 2.0 to open hangar_deck.gltf. The deck isn't on the level grid, and it's never joined to another room.

  2. Build. Move, add and reshape boxes. Everything that collides has to be a box. You can move, scale and rotate a box freely, but don't edit it into another shape or join several boxes into one object.

    What about everything else? Name it ..._NoCollision (the lamps, screens and the dropship's glass are), then add plain boxes named ..._CollisionOnly to stand in for its collision. The floor top is at Z = 0.

  3. Markers. The panel's buttons place each one at the 3D cursor:

    • Spawn_Player: where the squad comes in, facing the green (+Y) arrow.
    • Station_Console, Station_NeedsBoard, Station_Armory, Station_StarMap: the spot on the deck where each station is used from. A player within 2.2 m of it gets the station's prompt, so put it in front of the desk, board, bench or table, not inside it.

    If you move a station's furniture, move its marker with it. The game ignores the numbers Blender adds to duplicate names (Station_Console.001), so don't worry about those.

  4. Materials. Give each material its surface material with the Last Fleet Materials add-on (see materials.md). A material's Emission is added to its color, which is how you get a screen, a lamp or the engines' glow. Want something brighter than white? Set Emission Strength above 1.

  5. Check and export. Set Folder to content/modules/hub/, then press Check and Export. Export runs the check first and refuses if the deck breaks a rule. Otherwise it writes one self-contained hangar_deck.gltf. Commit the .blend (it goes through Git LFS) and the .gltf together. That's it!

You don't have to touch the export settings, because the add-on uses the ones the game expects: +Y up, modifiers applied, and Include > Custom Properties ticked (which carries each material's surface material). Then it folds Blender's binary output into a single text .gltf, so a clone without Git LFS still has the deck.

The rules

When the game loads the hub, it checks the same rules (HubLevel.Load):

  • a box for everything that collides;
  • one Spawn_Player;
  • a marker for every station.

If one is broken, it refuses the file and tells you what's wrong. The tests (HubLevelTests, and HubTests, which walks from the way in to every station) run in CI.

To see your deck, run LastFleet. The game opens on the ship, and --level hub goes straight there.
