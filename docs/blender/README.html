Art in THE LAST FLEET: start here

(If you're a designer tuning loot and weapons, start at the Studio reference instead. What can be added as data is listed in adding-content.md.)

Good news: everything you model goes into the game the same way! You work in a .blend file, export it with one of our Blender add-ons to a glTF file in content/, and the game reads that file when it starts. Reshaping a model doesn't need any code changes, so you never have to wait on a programmer.

This page is the overview. Each kind of model has its own guide with the details.

What Guide The game reads Your .blend goes in Add-on

Props: loot, containers, crates, the cargo pod and drone props.md content/props/<file>.gltf content/raw/props/ lastfleet_props.py

The add-ons are in tools/blender/. Install each one from Edit > Preferences > Add-ons > Install from Disk. They all put their tools on the Last Fleet tab of the 3D view's sidebar (N). Use Blender 4.2 or newer.

Whatever you're modeling, install lastfleet_materials.py too. It's how you give each material one of the game's surface materials (materials.md).

Had the VANGUARD add-ons installed? That was their name before the game had one. Remove them in Edit > Preferences > Add-ons (they're listed as VANGUARD Creatures, VANGUARD Rigs and so on), then install the lastfleet_*.py files in their place. Your .blend files don't need anything from you: the first time one opens with the new add-ons, its settings and every material's surface material move over to the new names. Save it, and that's done. The game still reads models exported with the old names too.

Getting set up (once)

  1. Install Git and Git LFS, then run git lfs install once. .blend files, images and sounds go through LFS. Skip it and you'll commit a pointer instead of your file... not great.
  2. Clone the repository and install the .NET 10 SDK to build and run the game: dotnet run --project src/LastFleet.Client.
  3. Install the add-ons for whatever you'll be working on.

The same everywhere

These rules hold no matter what you're making:

  • Axes. In Blender, +Y is the game's forward, +Z is up and +X is right. The add-ons export with the axes the game expects, so leave the exporter's settings alone.
  • Scale. One unit is one meter. For a feel of it: a room's walls are 3.6 m high, a cargo crate is 0.44 m high, and a rifle's body is about 0.4 m long.
  • Names. The game finds things by name. An object's name says what it is (Barrel_2_Heavy, Crate, Footlocker_Lid), and empties mark points (Muzzle, Hinge, Door). Blender's .001 suffixes don't matter. Each guide lists the names it uses.
  • Origins. A model's origin matters, because it's the point where the model stands or attaches. Where the model sits in the file usually doesn't matter, so go ahead and lay things out side by side. Apply rotation and scale before you export (Ctrl + A > Rotation & Scale).
  • Materials. Shading is flat: each face is lit by its own normal. A material's Base Color is its color, except for a few material names the game colors itself (a maker's finish on a gun, a rarity's color, a glow), and each guide lists those. How the color reacts to light (paint, bare metal, rubber, glass, a glow) is set by the material's surface material, which you pick from the game's library with the Last Fleet Materials add-on (see materials.md). Textures aren't used.
  • Check before Export. Every add-on has a Check button that tells you what the game would reject or ignore. Export runs it first, so you can't forget.

Committing your work

Happy with it? Here's how it gets in:

  1. Export the .gltf with the add-on, into its folder in content/.
  2. Save your .blend into content/raw/... (see the table above).
  3. Run the tests: dotnet test --solution LastFleet.slnx. They load every model and check its names, markers and sizes. CI runs the same tests on every pull request, so a broken file can't sneak in without anyone noticing.
  4. Look at it in the game. Each guide says how to get to it quickly (--pod, --horde, a level seed).
  5. Commit the .blend and the .gltf together, on a branch, and open a pull request. Done!

Grey-box starting files

Most of the models in the game started out as boxes written by scripts in tools/greybox/. Those scripts made the starting files you edit.

Never run one again over files someone has edited, because it would put the boxes back! If you want to start a new weapon frame or room from boxes, each guide says how to make just that one file.
