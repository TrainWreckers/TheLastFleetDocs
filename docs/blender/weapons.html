Modeling weapons in Blender

Every gun in the game is put together from part models: a receiver for its frame, plus a barrel, magazine, stock, optic and module picked by its roll. The models are glTF files in content/weapons/. This page shows you how to edit them and add more in Blender. The game reads them when it starts, so a new or reshaped part doesn't need any code changes!

Forged parts vs. Blender parts

Before you open Blender, there's a catch: the shipped part files are forged from recipes (docs/plans/weapons.md phase 5). content/weapons/forge.json holds every part's shapes (chamfered boxes, prisms, tubes, rails, vents, bolts, blocks) and markers, and the weapon forge writes the .gltf files from it.

You can run the forge two ways:

  • From Studio's Armory (Part models, tick Recipe): edit a part's shapes one per line, see it rebuilt, then Write files.
  • From the command line with dotnet run --project tools/LastFleet.WeaponForge -- content/weapons (--format also rewrites forge.json in its own layout).

A test fails if a part file doesn't match what its recipe makes. So if a part has a recipe, change the recipe, not the Blender file, because the forge would overwrite your Blender edit.

Each forged part has two child meshes besides its own:

  • Detail: small things only your own gun shows (rail ridges, vents, bolts).
  • Far: the part without its bevels and detail. Other players' guns are drawn with it, so the frame's moving triangle count stays low.

So where does Blender come in? It's still how you make a part that has no recipe. Take its recipe out of forge.json (or don't give a new file one) and model it as described below. The forge replaces the old grey-box kit (tools/greybox/generate_weapon_parts.py).

A brand-new frame only needs its file (forged or modeled) and an archetype in Armory > Frames whose model names it. No code needed. Too easy!

How a gun is put together

The game builds each gun the same way, whether it's in your hands, held by a soldier or lying on the floor:

  1. It takes the Receiver from the frame's file. That's the archetype's model in archetypes.json: a frame with "model": "auto_rifle" is built from auto_rifle.gltf, and frames can share a file. The receiver is the gun's body, and its origin is where the hand holds the gun.

  2. The receiver has sockets: empties named Socket_Barrel, Socket_Magazine, Socket_Stock, Socket_Optic, Socket_Module and Socket_Grip (the top of the pistol grip). The game attaches one part for that slot at each socket.

    A muzzle device (Muzzle_…, in shared.gltf) goes on the barrel's Muzzle, scaled to the barrel's thickness at that point, and its own Muzzle marks the new end (where the flash appears).

    No socket for a slot? Then the frame has no part there. The hand cannon has no Socket_Stock, and the shotgun, hand cannon and grenade launcher have no Socket_Magazine (their pump, cylinder and drum are part of the receiver or barrel).

  3. Which part. A slot's options are the parts named after it: Barrel_<anything>, Magazine_<anything>, Stock_<anything>, Module_<anything>, Grip_<anything>, Muzzle_<anything>, in name order.

    Every part in the loot data (parts.json) names its model, either in full ("model": "Barrel_2_Brake") or by its shape, which is the last word of the name ("model": "Brake"). A shape name picks that look on every frame, and a frame without that shape shows its first one. "None" shows nothing in the slot (a bare rail). A stock (unrolled) weapon uses the first.

    A part that doesn't name a model gets one picked from its id (and adding a model to the slot reshuffles those), so give it one.

  4. Which optic. The optic part decides. Its model names the kind, Iron, RedDot, Holographic or Scope (which picks the first of Optic_Iron, Optic_RedDot, ...), or one specific look in full (Optic_RedDot_Round). A gun with 2× magnification or more (the marksman rifle's frame) ALWAYS carries a scope, whatever optic is fitted.

  5. Stretching. A barrel is stretched along its length based on the weapon's range, from 0.85× to 1.15× of the model. A magazine is stretched along its height based on its capacity, so model it 0.16 m long, which is the middle size.

  6. Colors. Some materials are colored by the game. The rest keep the Base Color you give them:

    Material Color in the game
    Body The maker's finish: its color in manufacturers.json (Kessler olive, Halcyon white...; gunmetal if it has none)
    BodyDark, BodyShade The maker's finish at 85% and 80% brightness
    Accent The rarity's color: the stripe along the side
    Reticle A glowing red, for an optic's dot
    Lamp A glowing white, for a weapon light's lens
    Paint_<Slot> A paint slot: a color the part's data picks (its paint in parts.json, by slot), with its Base Color as the default
    anything else Its own Base Color

    The names above are reserved, because the game colors them. Paint slot (next to Kit materials) adds a Paint_<Slot> material to the selected faces. A slot name is letters, digits and underscores, starting with a letter.

    Check reports any misused name:

    • a paint slot named after one of them (Paint_Accent);
    • a prop's game color on a gun (Glint, Light; on a gun they keep their own color);
    • a reserved name with different capitals (body).

    How each material reacts to light is set by its surface material, which you pick with the Last Fleet Materials add-on (materials.md). In the kit, Body and Accent are painted metal, Metal is bare metal (a barrel's clean streak), Grip is rubber, Glass is glass, and Reticle and Lamp are emissive.

Shared parts. content/weapons/shared.gltf holds parts any frame can use: the red dot, holographic sight and scope, the modules, and the muzzle devices (brake, flash hider, suppressor). A frame only uses the shared parts for a slot when its own file has none for that slot.

So to give the shotgun its own red dot, add an Optic_RedDot to shotgun.gltf, and every other frame keeps the shared one. That's why the hand cannon's file has its own modules: it has no fore grip, so its third module, Module_2_None, is an empty.

Markers.

  • Each barrel has an empty named Muzzle where the flash appears.

  • Each optic has an empty named Sight, which is its aim point. When aiming, the game holds the gun so this point is on the eye line. Put it in the middle of the optic's window, or on the tip of the front post for iron sights, and keep everything except the reticle clear of the line through it along the barrel.

    A red dot's or holographic sight's Reticle triangles aren't drawn. Instead the game puts a pane of sight glass across the window at Sight, and its reticle (the part's reticle: dot, ring or chevron) stays on the aim point however the gun sways, just like a real one does! Keep the window's frame around Sight.

  • The receiver has two more, Grip.R and Grip.L: where the right hand holds the pistol grip and the left hand holds the fore grip (a shotgun's pump; on a pistol the left hand cups the right). Bodies drawn on a rig hold the gun by these. The gun hangs from the right hand, and the left arm reaches for Grip.L. A receiver with no Grip.L is held a third of the way to the muzzle.

  • Parts can mark where hands go on them too (docs/plans/weapons.md):

    • A fore grip module or a barrel (a handguard) can have Hand.L, which the left hand uses instead of the receiver's Grip.L (an unmarked grip module is held around its middle).
    • A magazine can have Grab, where the hand takes it during a reload (unmarked: low on its front).
    • A receiver can have Charge, the charging handle or bolt worked after a reload from empty (unmarked: high on its right side).

  • A module can have Laser, where a laser's beam starts.

  • A scope marks its eyepiece with Eyepiece (the middle of its back window) and EyepieceRim (a point on that window's edge). When aiming, that window is what you look through, and the gun behind it isn't drawn.

  • The magazine goes in at Socket_Magazine and comes out along its -Y.

Directions and scale

In Blender, the gun points along +Y, +Z is up and +X is the right side. Units are meters, so a rifle's receiver is about 0.4 m long. A part's origin is where it attaches:

  • a barrel's origin is its back end, at the receiver, and it runs forward along +Y;
  • a magazine's origin is its top, where it enters the receiver, and it hangs down;
  • a stock's origin is the receiver's back, and it runs back along −Y;
  • an optic's origin is the bottom of its mount;
  • a module's origin is under the front of the receiver.

Where a part sits in the file doesn't matter, so we lay parts out side by side to work on. Rotation and scale DO matter, so apply them (Ctrl + A > Rotation & Scale) when you're done. Want to see a part in place? Move it onto its socket while you work, since its position is ignored on export.

Setup (once)

  1. Install Blender 4.2 or newer.
  2. In Blender, go to Edit > Preferences > Add-ons. Choose Install from Disk, pick tools/blender/lastfleet_weapons.py, and tick Last Fleet Weapon Parts.
  3. In the 3D view, press N to open the sidebar. The tools are on the Last Fleet tab, under Weapon parts.

Editing a frame

So you've got a frame to rework? Here's the flow:

  1. Open it. Start an empty file (delete the default cube, camera and light) and use File > Import > glTF 2.0 to open content/weapons/<model>.gltf, for example auto_rifle.gltf. Save the .blend in content/raw/weapons/ (it goes through Git LFS) so the next person starts from your file.
  2. Kit materials. Press Kit materials. It adds any of the materials above that the file is missing, and shrinks the imported markers from the meter-wide size Blender shows them at down to 3 cm.
  3. Model. Edit the parts in Edit mode, or replace them: delete a part, model a new one, give it the old part's name and move its origin to the attach point (Object > Set Origin). Use as many materials as you like. Meshes parented under a part are part of it.
  4. Markers. To add a socket, a Muzzle or a Sight, select the part it belongs to, put the 3D cursor where it goes (Shift + right-click), and press its button. It gets parented to the part for you. Blender's .001 suffixes don't matter, so every barrel can have its own Muzzle.
  5. Check. Press Check. It lists problems in the status bar and the Info editor:
    • a name that isn't a part;
    • a barrel with no Muzzle, or an optic with no Sight;
    • a receiver with no barrel or optic socket;
    • a marker that isn't parented to a part;
    • a misnamed material (see above).
  6. Export. Set Id to the file name (auto_rifle, or shared for the shared parts; it defaults to the .blend name), set Folder to content/weapons/, and press Export. It runs the check first, then writes one self-contained .gltf with every part, including hidden ones.
  7. Try it. Run the tests (dotnet test tests/LastFleet.Client.Tests). They put every frame together and check its sockets, muzzles and aim points, and that aiming looks through the sight. Then play the game: the gun in your hands, the soldiers' guns and the weapons on the floor all use these models. Commit the .blend and the .gltf together.

Adding a part

Let's say you want an eighth barrel on the auto rifle. Add an object named, for example, Barrel_7_Long to auto_rifle.gltf, with its origin at its back end, pointing along +Y, and a Muzzle empty at its front. Export. That's it! Rolled auto rifles now pick from eight barrels.

A couple of gotchas:

  • The shipped auto_rifle.gltf is forged, so for that one you'd add the barrel to its recipe instead.
  • Shared parts lose to a frame's own. For a part every frame can use, put it in shared.gltf, but remember that a frame with its own parts for that slot ignores the shared ones.

To make a part in the loot data use it, set that part's model to Barrel_7_Long, or to Long to use that shape on every frame that has one. You can do this in Studio's Armory, where the field opens a 3D picker of the slot's models, or by hand.

See it right away in Studio. If LastFleet Studio is open in Armory mode when you export, it picks up the change. Studio reads the repository's content/weapons and reloads a file as soon as it's written (the status line tells you, or tells you why it couldn't load it).

  • Part models on the 3D panel shows every model for a frame's slot on a turntable, along with the data parts that use it.
  • The rolled gun shows the previewed gun put together.

The rules

Rule Why
Each top-level object is a part, named Receiver, Barrel_…, Magazine_…, Stock_…, Module_…, Grip_…, Muzzle_… or Optic_<Iron, RedDot, Holographic or Scope>…. The name says which slot it fills.
A frame's file has a Receiver with at least Socket_Barrel and Socket_Optic. Every gun has a barrel and a sight.
Every barrel has a Muzzle, and every optic has a Sight. The flash and the aim come from them.
Markers are empties parented to their part. Meshes can be parented too. A part is the object plus everything under it.
A paint slot is Paint_<Slot>. Body, BodyDark, BodyShade, Accent, Reticle and Lamp belong to the game. The data colors paint slots, and the game colors the rest.
Only meshes and empties. Modifiers are applied on export; armatures, curves and text aren't exported. The game reads triangles and empties.
