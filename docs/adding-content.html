Adding content: what is data, and what still needs code

So you want to add a new gun, a room, an enemy? Good news: most things are data! That means a new entry in a JSON file under content/defs/, plus art under content/ if it needs a model. None of it needs a programmer or a build.

You can edit the data in LastFleet Studio (the Studio reference) or by hand. Studio picks up hand edits as soon as you save them, so use whichever you like.

In Studio, every list has a + New button. It adds an entry at the end of the list, copied from the one you have selected (or the first one), so every field is already filled in. Give it an id and a name, then change whatever makes it different. Too easy!

Not sure what something does? The text above the fields says what the list is for, and hovering over a field tells you what it does. Fields that point to other entries (a rarity, a maker, a frame) are picked from a list, so you can't make a typo.

The tables below go area by area: what you can add, where it lives, what to set, and anything else it needs.

Guns and loot (content/defs/loot/)

To add Where What to set Anything else?
A maker Armory > Makers (manufacturers.json) id, name, color (its paint), models (the model names it sells for each frame it makes), bias (stats applied to all its guns), signature (its trait), weight, minRarity Optional: give it its own parts (set their manufacturer to the maker's id). Loot tables can favor it under manufacturers.
A part Armory > Parts (parts.json) slot, mods, rarity, weight; manufacturer to limit it to one maker; archetypes to limit it to some frames; model for the model it shows as Its model goes in the frame's file in content/weapons/ (weapons.md). The model field opens a 3D picker with icons for that slot's models. The 3D panel's Part models shows every model and which parts use it.
An affix Armory > Affixes (affixes.json) kind (prefix or suffix), rarity, weight, mods, traits
A frame (archetype) Armory > Frames (archetypes.json) model (its models file), firing (hitscan, pellets or projectile), frameStats (rate of fire, magazine, damage, spread...), base stats, clamps; sound, kit, sidearm and grip (how a body holds it, animation-graphs.md); soldier (how an enemy soldier fights with it: damage and range scales, how long it holds the trigger, its squad role) Its models go in content/weapons/<model>.gltf, made in Blender (weapons.md). Frames can share a file. A maker has to list models for the frame before it makes it, and a loot table has to name the frame before it drops. Enemy variants carry it once their weapons list it. Its shot sound is the cue gun_<model> (content/defs/sounds.json, sound.md), unless sound names a different one.
A rarity Loot > Rarities (rarities.json) color, weight, perLevel, affixes, statBonus, mods Tiers rank in file order, lowest first.
A relic Loot > Relics (relics.json) archetype, manufacturer, five parts, traits, affixes, flavor It never drops unless a loot table entry names it ("relic": "<id>").
A loot table Loot > Loot tables (tables.json) entries (frames, other tables, relics; weights and item levels), rarity and manufacturers bias Something has to roll on it: a mission's loot settings or another table. Never change a table that has shipped, because guns are rebuilt from their table.
A trait's strength Armory > Trait rules (traits.json) The numbers for each trait A new trait (a new effect) needs code.
An item (a medkit, an ammo pack, a fleet supply, a raw material...) Items > Items (items.json) id, name, model (file/Object in content/props), paint, color, stack; flags: consumable (useSeconds, and the effect it runs), fleetSupply, refinable (a raw material), weaponPart (fitSeconds), carried (held in both arms, like a crate) Put it in item tables so players can find it lying around. There's a limit of 64 items, and the order matters (it's how items are sent over the network), so add new ones at the end. An item that does something the game can't do yet needs code (see below).
An effect (what an item does: healing, armor, a shield, a stat change for a while, refilling ammo, calling a pod, or a mix of these) Items > Effects (effects.json) id, name, trigger (use: from a quick slot; passive: while its item is held), actions in order. Each action is a do: heal with amount; giveArmor with amount, max; shield with amount, delaySeconds, perSecond; changeStat with stat, by, seconds; refillAmmo with magazines; callPod; placeDevice with fuseSeconds, blastRadius, blastDamage; sound with cue; flash with color, brightness, radius, seconds A consumable item names a use effect in its effect. Any item can name a passive effect in its passive. Try one out with --give <item>.
A fleet supply's rules (how much a jump uses, what happens when you run short or have enough, its stations) Items > Supplies (supplies.json) item (an item with fleetSupply), use (each one a per: jump, ship, damagedShip, people with people and round, shipAlive with ship, contact; plus its amount), short (each one a do: peopleLost, morale, shipWorn, message), stocked (morale, repairShips, produce), jumps, boarders, startJumps, stations Every fleet supply item needs rules. A new supply's crates come from item tables, and its stations get added to the star map. Whether a station keeps it in tanks is the mission's (tankKinds and the reservoir's supplies).
A kind of tank, or the fittings for the reservoir or the airlock A model in content/props (in Blender, see docs/blender/props.md: station.gltf's Tank, with Hose, Gauge and Gauge_Top), then Missions > tankKinds (station_raid.json) model, supplies, radius, height, weight; for reservoir: model, outlet, valve, radius, height, supplies; for airlock: intake and chute Collision is boxes only (..._CollisionOnly). Whatever the tank kinds hold is everything a station keeps in tanks. Run the gate tests, since a solid fixture in the way can break a seed.
An item table (what a supply pile, a footlocker, a case or a cargo crate holds) Items > Item tables (items.json) entries: an item (by id), its weight, count and perDeck A mission names it in its loot (pileTable, footlockerTable, caseTable, cargoTable). A cargo crate only holds fleet supplies.
A grade of refined material (Mk I...) Items > Grades (crafting.json) id, name, itemLevel (the item level that things made from it roll at), color Lowest first. Recipes make it, refinery tiers unlock it, fabrication spends it.
A refinery tier (the fleet's refinery upgrades) Items > Refinery tiers (crafting.json) cost (fleet supplies, by item id), grades it can make, batches per jump Lowest first. A fleet starts at the first tier and upgrades from the needs board.
A refinery recipe Items > Recipes (crafting.json) inputs (raw materials, by item id, and how many), grade, gives The refinery makes the best grade it can first.
Something the armory fabricates Items > Fabrication (crafting.json) makes (a weapon from a loot table, a part for a slot, or anything), grade, cost Players drag it at the armory bench on the ship. It rolls at the grade's item level.

Missions (content/defs/missions/)

To add Where What to set Anything else?
A mission template Missions > + New mission (a copy) (a new file) Decks, rooms, loops, soldiers, stories, built rooms, and its loot tables The game plays station_raid.json and ship_raid.json (campaign.json says which a star map target uses). You can make and check a new template in Studio, but playing it needs code (see below).
A station's tanks and deep reservoir Missions > the template (station_raid.json, ship_raid.json) tanks, tankAmount, tankFill, hoseLength, pumpRate; reservoir: chance, amount, junctions (valves along the way), valveSeconds, pumpRate The reservoir sits deeper in than the hose can reach, and it's piped to an outlet near the airlock.
A ship raid (a mission laid out by a plan) Missions > ship_raid.json > laid out by a plan (plan) plans (weighted), zones, routeLength, keycard (rooms by tag, offRoute, detourChance), objective (kind: hack, data or destruct, rooms, archetype, seconds, countdown, sealEvery) or objectives (several, each with a weight), insertion and extraction (exits: hangar, airlock), pods (perZone, seats), closets, threat (zones, districts, rooms, reinforcements: everySeconds, size; sources) The game plays one as --level frigate:<seed>, carrier:<seed> or any plan's id (accreted_station:<seed>). Run the gate tests (-class "*GateSeeds*") after a change. The lobby can force an objective kind (-o<kind> in a level's settings).

Levels (content/defs/procgen/)

To add Where What to set Anything else?
A tag (a room type, a style, a zone) Levels > + New tag (tags.json) Its dotted name (room.storage.cold) and what it means Rules that use tags come with the next phases of the procgen revamp (plans/procgen-revamp.md).
A room archetype (a kind of room built from the seed) Levels > Archetypes > + New archetype (archetypes.json) Its shape (a kind with its ranges, or a stamp drawn on the grid), tags, roles, style, furniture (a furnishing in rules.json), cut corners, pillars, weight and roomDoor (its doors in a ship's level: auto or interact). Set vertical for a tall room: the stories slider goes up to 4. Each story above the ground gets a gallery, mezzanine, catwalks, landing or nothing, 2.5 to 8 m deep. Stairs are generated, either straight or switchback, running up from the nearest floor below where they fit and through any open stories in between. A room with a floor that needs stairs has to be at least 4 cells each way. A template builds rooms from the archetypes it lists (Missions > the template's archetypes). A template never draws an archetype taller than its own stories.
A room in a biome's kit (a room every level in the biome has: a corridor, the insertion bay, a hangar to extract from) Levels > Archetypes > + New archetype, with kit (archetypes.json) The same as an archetype, plus kit (the biome: station). For a rectangle of a fixed size, also doors (each one a side, a cell and a level; one-cell sides are allowed). It can also take the mission's roles (insertion, corridor, closet, key, objective, extraction). Set vertical with a landing for a stairwell. Nothing else. The kit is built once from each room's id and offered to every level. If a role needs a spot in the room, the room gets it from its roles (the insertion's spawns, the extraction's spot) or from a prop its furnishing places (a terminal's marker). If a furnishing's required rules can't be met in any of six footprints, the kit stops and names the room.
A surface style (how rooms or halls look) Levels > Styles > + New style (styles.json) Its id, its base, and what's different from the base: walls, floor, ceiling, trims, duct, pipes, lights, and how a hall built in it looks (hall) A deck theme builds its halls in the style it names (style under the template's hallThemes). Rooms built from the seed use their archetype's style. In later phases, rules will pick styles for kit rooms.
A prop (something rules place) Levels > Props > + New prop (props.json) Its kind (furniture, footlocker, case, cargo, supplies, ammo, keycard, tank) and size. For furniture: a model (picked from content/props, and its size comes from the model) and its paint, or its color, what it breaks into and its piece's name, and which mission spot it stands for (marker: terminal, extraction or key; markerAhead is how many meters in front of it) A rule that places it (Levels > Rules). A tank's size and model come from its kind in the mission template.
A furniture model (a table, a chair, a rack) A recipe in content/props/forge.json, edited in Levels > Props > Its recipe, or a model in a new content/props file (docs/blender/props.md) Its parts and materials, its solid boxes, Socket_<Group>_<n> empties where loot sits, and Attach_<Group>_<n> where another piece stands A prop that uses it. Then on the prop, set sockets (each group's loot table, chance and count) and attach (what stands at each group, and how far it's pulled out). Collision is boxes only, and a piece that breaks is one box.
A placement rule (what goes where in rooms) Levels > Rules > + New rule (rules.json) What (props and weights), where (a tag query), anchor and fallback, count, clear space, spacing, priority, blocks, interaction, required. Set arrange for a row or grid (gaps, aisles of 1.1 m or more, back to back). Nothing else. The level's rules apply to every station level. You can see how a rule did in a room on the Missions mode map.
A furnishing (how a built room is furnished) Levels > Rules > + New furnishing (rules.json) Its rules (with no where, since they apply to the room being furnished) An archetype that names it (furniture), or built rooms that draw one.
A loot assignment (what loot a kind of room gets) Levels > Loot > + New assignment (loot.json) Where (a tag query: role.*, deck.*, layout.*, or the content's tags), and any of these: a cache (table, count), a stash weight (per room deeper, per soldier carrying it; table), the tables its piles, footlockers, cases and cargo roll from, and added item levels Its tables have to exist in the loot data (Checks will tell you). Order matters: the first cache and table win, while weights and levels add up.
A recipe step (how a mission's decks grow) Missions > the map's Recipe view > + side rooms or + loot rooms (the template's recipe) How many per deck, how often a side room is two deep, and which decks (leave it out for every deck). Move it with < Earlier and Later >. The main path and the keycard steps stay as they are. The node shows the mission's graph after the step runs.
A typing rule (what mix of rooms a level has) Levels > Typing > + count, + adjacent or + distance (typing.json), or a tick in the Adjacency table A count (where, per deck or level, min and max), an adjacency (rooms a and b are never connected) or a distance (min and max steps between rooms a and b), all by tags; plus the kit's share If a rule set can't be satisfied, the level stops and tells you why. Try a few seeds in Missions mode (Types).
A network's costs (where a pipe runs) Levels > Networks (networks.json) What its route pays for each direction it can run and each bend, its open span and service cells, and its pipe's look The generator lays reservoir_feed. A new network only gets laid once code asks for it. You can see its route on the Missions mode map.
A level plan (a ship's or a station's shape) Levels > Plans > + New plan (plans.json) Its parts (a hull, boxes, arms, rings, painted cells), its halls (spines, cross passages, rings, service ways) and its sections; its decks (names, districts) and stair cores; parts and halls name their decks Its rooms come from its sections' districts; its mission comes with the next phase of the structure-first plan (plans/structure-first.md).
A pin (a set piece held in place on a plan) Levels > Plans > Its pins > + room pin or + boarding pin, then drag it on the preview (plans.json) pin (room or boarding, the squad's airlock; one boarding pin a plan), archetype for a room, on (the part), at (along it, 0 to 1), across (cells off its line) or offset (cells from a ring's center), deck A room pin's room is cut round where it's pinned (the bridge at the bow). A boarding pin picks the airlock or hangar nearest it.
A district (what a section's rooms are) Levels > Districts > + New district (districts.json) Its anchor and its rooms: archetypes with widths, weights, runs and private A plan's sections name it.

Enemies and their behavior (content/defs/ai/)

To add Where What to set
An enemy variant (a new kind of soldier) Behavior > Enemies, + New (enemies.json) behavior (which behavior file it thinks with), body and model (what it's drawn as: an animation graph in content/anim and a model in content/characters; see rigs.md), faction (hostile or choir), health, damageScale, grenades, runSpeed, sprintSpeed, dropsLoot, weapons (frames and how often each is used), spawns (how often this variant shows up in the level's squads, reinforcements, the director's patrols or the Choir), clips (its own clips in place of the body's, animation-graphs.md)
A behavior (how a kind of soldier thinks) Behavior > Behaviors, + New behavior (a new file next to soldier.json, named after its id) Its tree, built from the palette (right-click the canvas), and its scoring if the tree picks an intent. Then pick it as a variant's behavior.

And inside a behavior's scoring:

To add Where What to set
A personality Behavior > Behaviors > Scoring (right-click the graph background) share (how many squads get it), flankers, cohesion (how many meters its soldiers stay within each other), and a scale for each intent
A term, factor or condition Behavior > Behaviors > Scoring Right-click the canvas for the palette (or drag from an input and let go on empty canvas), then wire it to an intent's or term's pin

Still in code: ask a programmer

We're not all the way there yet. These are the places where adding or changing content still needs code, so grab a programmer for these. Each one is on the list to move into data.

What Where it is Why it's still code
A new way of firing (beyond hitscan, pellets and a flying round) WeaponHandling, WeaponFiring It's new behavior. Any frame that fires one of those ways is data.
A new trait (a new effect) WeaponTraits, WeaponTraitSystem It's new behavior. Its strength is data (traits.json), but its card text is still in WeaponCard.
An effect that does something new (an action beyond the ones above, or a new stat to change), or a fleet rule beyond what a supply's rules cover (a new kind of use, shortage or bonus) a record under LastFleet.Simulation/Effects (EffectAction), EffectRunner, EffectReader.Actions and Studio's LootGlossary.Variants; a record under LastFleet.Simulation/Supplies, FleetSim, SupplyReader It's new behavior. Any effect built from the existing actions, and any supply rules built from the existing parts, in any order and amounts, is data.
What a soldier drops besides its gun SoldierLoot Not moved yet.
Which mission template a mission plays (the lobby uses the station raid; the star map the station or ship raid) Levels, StarMap Levels loads each template by name.
Bark lines (what soldiers shout) BarkLines Not moved yet.
The reasons shown over a soldier's head IntentReason A term can only give one of the reasons the game already knows.
How a gun's power number is worked out, and how tall a loot beam is for each rarity WeaponRoller, GameView Not moved yet.
The horde's and the director's tuning HordeTuning, DirectorTuning Not moved yet. (The soldiers' tuning is data: content/defs/ai/tuning.json, one per side, edited in Studio's Behavior mode, Tuning tab.)
