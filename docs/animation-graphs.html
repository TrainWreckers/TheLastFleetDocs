Animation graphs

A soldier is running, crouching, leaning out of cover and reloading, sometimes all at once. Which clip plays? That's the job of a body type's animation graph: it decides how its rig's clips get blended into a pose, based on what the body is doing. If you've used Unreal's anim graphs, this'll feel familiar.

The graph is a file, content/anim/<id>.json (the humanoid's is humanoid.json), shared by every model on the rig. It sits next to the clips it plays (content/anim/<rig>.gltf; see rigs.md), and it's part of the plan in plans/animation.md. Soldiers and the Choir's lancers use it: each enemy variant names its body (the graph) and its model in content/defs/ai/enemies.json.

The game and the graph only talk through two things:

  • Parameters: numbers the game sets for each body every frame from its state (how fast it's moving and which way, crouched, leaning, dead).
  • Actions: what the graph plays when the game says the body does something (a reload, a throw).

That's it! The behavior that decided to crouch never names an animation, and the graph never knows why the body crouched. The code that sets the parameters is the body type's bridge (the humanoid's is HumanoidBridge). If the graph doesn't declare a parameter, it just doesn't get set.

The file

Key What it is
id, name The graph's id (the file name) and its display name.
rig The rig it poses. Its clips and masks have to belong to that rig.
clips The file with the rig's clips, in content/anim (humanoid.gltf).
parameters Each one has a name, a default (0 if not given) and a description (about). Flags are numbers: 1 is on, 0 is off. min and max (default 0 and 1) and flag are only for Studio's sliders and checkboxes; the graph accepts any number.
targets The points its IK reaches for, each with a name and about. The game supplies them while the graph plays (for example, the humanoid's leftGrip is where the gun's fore grip is).
capabilities What a body of this type can visibly do: fire, reload, throw, crouch, lean, blindFire (the humanoid has all of them). An enemy variant's behavior can only need these. A behavior's needs come from its tree (Hold cover needs crouch, lean and blind fire; Throw grenade needs throw). If a variant's behavior needs more than its body can do, it gets flagged (in Studio's Enemies tab and in the game's log). fire, reload and throw also need a graph action with the same name.
actions One-off things the body does on top of everything else, played into the graph's slot node (below). Each has a name (the game's name: reload, throw, fire, use), the rig clip it plays, the mask it covers (the whole body if not given), fadeIn and fadeOut (seconds, default 0.1), about, and events. Events are moments in the action, each with a name and an at value from 0 to 1 giving how far through the action it happens. For example, the humanoid's throw has release at 0.55, when the grenade leaves the hand. Because it's a fraction, the event stays in the right place however long the action lasts and whichever clip a grip plays for it.
groundSpeed The parameter that holds the body's speed over the ground, in meters per second. Clips played by stride use it.
root The node at the top of the tree. Its output is the pose the body is drawn in.
pos, loose Only Studio uses these; the game ignores them. pos (on the graph or any node) is where the node sits on the graph editor's canvas. loose holds nodes that aren't plugged into anything, each as { "node": ... }, until you plug them in or delete them.

A value in a node is either a number (0.5) or the name of a parameter ("leanLeft").

Nodes

A graph is a tree of nodes, with poses flowing up from the leaves to the root. Each node is an object with exactly one of these keys.

Node Keys What it does
clip clip (its name), loop (uses the rig's setting if not given), time, stride, rate, normalized, events Plays a clip. time says where the clip's time comes from. "clock" is the default: it starts from the beginning each time the clip starts playing, then runs with real time, multiplied by rate. "stride" uses the ground covered: one loop every stride meters, so the feet keep pace. "end" holds the last frame. A value means seconds into the clip, or with normalized, a fraction from 0 to 1 regardless of its length.
blend1d blend1d (a value: the axis), points (each with an at number and a node, in order along the axis), sync Blends the two points on either side of the value, weighted by how close it is to each. For example idle at 0, walking at 1.8, running at 4.5, by speed.
blend2d blend2d (two values: across and up), points (each with an at of [across, up] and a node), sync Blends points on a plane, for example a stride in each direction, by which way the body is moving. Between two neighboring points, only those two count.
select select (its states, each with a node and a when), fade (seconds, default 0.2) Plays the first state whose when is true, fading from the previous one when it changes. The last state can leave out when, so it's picked when none of the others are. when can be dead (flag on), !dead (flag off), speed > 2 or speed < 2.
layer layer (the node underneath), over, mask, weight (a value, default 1), fade Plays over on top of the node underneath, only on the rig's mask. For example, a reload from the spine up on top of running legs. The weight eases toward its value over fade seconds. While the weight is 0, the over node isn't played at all (a clip on its clock restarts the next time).
slot slot (the node underneath) Where the body's actions play, like Unreal's slot node with montages played into it. On top of the node underneath, it plays the clip of the action the body is doing, on the action's mask, from the clip's start to its end as the action goes from 0 to 1. So the clip lasts exactly as long as the action: a reload gets stretched to the gun's reload time. An action fades in when it starts and fades out when it's done. If another action replaces it, the current one fades out first and then the next one fades in. A graph has only one slot.
additive additive (the node underneath), add, reference, weight, mask Takes the difference between add and reference (for example leaning out, compared to standing) and adds it on top of the node underneath, scaled by weight.

IK nodes

Clips get the pose close, but they don't know the floor is uneven or where your gun's fore grip ended up. That's where IK comes in. IK nodes bend the pose underneath them after it's been blended. They use the rig's chains (content/rigs/<id>.json). A chain is a run of bones from root to tip, plus its pole, which is the direction its middle joint bends.

IK nodes ask the game where things are in the world, so when there's no world (Studio's preview, a test) they do nothing.

Node Keys What it does
reach reach (the node underneath), chain (three bones: two plus the tip), target, socket, weight, fade, swing Bends the chain so its tip, or the rig's socket on it, lands on the target. The middle joint bends the way the clip had it, or toward the chain's pole. The tip keeps its rotation (a hand stays the way it was held). The weight eases over fade seconds. If the target is out of reach, the bone the chain hangs from (a shoulder) turns toward it, up to swing radians (default 0).
look look (the node underneath), chain, pitch, yaw, shares, weight Turns each bone in the chain up by pitch and left by yaw (in radians), each by its share (shares, root first; split evenly if not given). This is how the spine and head bend toward the aim and carry the arms and gun with them.
ground ground (the node underneath), chains (the legs, three bones each, all hanging from one pelvis), weight, range, ease Checks how high the ground is under each foot and moves the foot up or down by that much from where the clip had it on flat ground (at most range meters, default 0.4). The pelvis drops by the lowest foot's amount so the legs can reach. Each foot's height follows the ground at one meter every ease seconds (default 0.25). Works with two feet or up to eight.

Sync

Ever seen a character's feet shuffle weirdly as it speeds up from a walk to a run? That's two strides out of step. A blend with sync keeps the strides under it in step. They share one phase, advanced by the ground covered divided by their blended stride, so a walk blending into a run keeps the feet together. A stride clip outside a synced blend keeps its own count of the ground.

Events

Events are moments on a clip: "events": [{ "at": 0.53, "name": "footstep" }], in seconds into the clip. You place them in Studio on the clip timeline under the Bodies preview, by dragging them to the right frame. An action's events fire the same way when the action passes them (every time it's done), and they're reported with the action's clip.

An event (on a clip or an action) can also say what it does, like Unreal's notifies. It can have:

  • sound: a cue in content/defs/sounds.json, played where the event happens;
  • gain: how loud (default 1);
  • effect: dust kicked up, sparks;
  • socket: the rig socket it happens at, like Grip.L (the feet if not given).

So a footstep looks like { "at": 0.333, "name": "footstep", "sound": "step", "gain": 1.2, "effect": "dust" }. The game plays and shows these for every body drawn from the model.

A couple of gotchas:

  • Blended strides don't double up. When several blended strides pass the same event, it only counts once, and a stride weighted at less than a quarter of the pose is left out.
  • Events replace distance footsteps. A body whose events play step makes footstep sounds from those events instead of from the distance it walks (sound.md).
  • Studio catches typos. It flags a sound that isn't a cue, or an effect the game doesn't show.

Each frame, a body reports the events it passed along with how much of its pose that clip made up (so a footstep from a walk that's half blended away is half as heavy).

Clips chosen by who plays it

The graph is one template for every body of its type. But a soldier holding a hand cannon shouldn't hold it like a rifle, right? So whoever plays the graph can swap the clips it names, without needing a graph of their own. This works like Unreal's per-weapon animation layers (Lyra gives each weapon its own).

  • The gun's grip. Each weapon frame has a grip (content/defs/loot/archetypes.json; in Studio: Armory > Frames, the frame's grip). rifle is the default and plays the rig's own clips. pistol (the hand cannon) plays the rig's Pistol_ clips instead, wherever the rig has one: Pistol_Idle for Idle, Pistol_Reload for Reload, Pistol_Fire for Fire, and the rig's normal clips for everything else (the strides). A new grip is just clips, not code. Name them <Grip>_<Clip> on the rig (Heavy_Idle) and frames can pick it (Studio offers every grip the rig has clips for).
  • The enemy variant. A variant's clips (content/defs/ai/enemies.json; in Studio: Behavior > Enemies) swaps in its own clips for the body's: "Idle": "Lancer_Idle". The grip is applied first, then the variant. So to change how a variant holds a pistol, swap Pistol_Idle, not Idle. A clip name the rig doesn't have is never played (Studio warns you).

The choice is made once per grip and variant and then kept (AnimPlayer.Choose, a ClipChoice set on the body's AnimInstance.Clips), so it costs nothing per frame! Studio's Bodies mode plays it the same way the game does: the gun picked under Holding plays its grip's clips, a Variant plays its own, and the parameters panel lists which clips are being played in place of the graph's.

The humanoid's graph

Want to see how it all fits together? Here's the one we ship. At the top, a select picks between dead, downed and alive. Alive is built from these pieces:

  • The legs' locomotion: a select between crouched and standing. Each is a blend1d by speed, from standing still to a synced blend2d of the four strides by movement direction.
  • The arms holding the gun the way Idle holds it, layered on top. So a grip's own Idle (a pistol held out) is also how the arms hold the gun while walking and running. The rig's strides already hold a rifle the same way its Idle does, so for a rifle this changes nothing.
  • Blind fire, layered on top from the spine up.
  • The slot where actions play (a reload, a throw, a shot's kick).
  • Leaning, added on top of all of it.

Then IK runs: the feet are set on the floor, the spine and head bend toward the aim, and the hands go on the gun (its grips are markers on its receiver, see weapons.md).

Other players' guns hang from their right hands, pointed along their aim, and the left hand reaches for the fore grip. Your own gun, in first person, is wherever the view holds it, and both hands reach for it. If the fore grip is out of reach, the left hand slides back along the gun toward the magazine well, and the shoulders swing forward to reach.

Your own body

Look down in first person and you'll see your own body: the player model (content/characters/player.gltf), under your eye, playing the same graph as everyone else. The camera is still the simulation's eye; the body is moved to sit under it.

The head (the rig's firstPersonHides mask) isn't drawn, otherwise you'd be staring at the inside of your own face. The body and gun are drawn in front of the world, so neither one clips through a wall you're standing against. --floating-gun shows just the gun, the old way.

Parameter Set from
speed The simulation's horizontal speed.
moveForward, moveRight The direction the body's feet move from frame to frame, in the body's own axes (a unit direction; kept when it stops).
crouched Crouching or sliding.
leanLeft, leanRight How far it leans around cover (the simulation's Lean, fully out at 0.45 m).
blindFire Firing blind over cover.
downed Down and waiting for a revive.
dead, deadSeconds Dead, and for how long.
aimPitch How far up the view is aiming (radians). It's 0 while firing blind, so the head stays down.
leftHandOnGun 1 unless reloading, throwing, using an item or downed. Otherwise the left hand lets go of the fore grip so the clip can move it. A gun whose frame has step-by-step reload (content/defs/reloads.json) keeps it at 1 during the reload, and the hand follows the steps instead of the clip.
rightHandOnGun 1 for your own body in first person: the gun is where the view holds it, on the aim, and the right hand reaches for its grip (rightGrip). Other players' guns hang from their right hands.

Whatever the hands are doing plays the graph action with that name, at how far through it is: reload during the reload (stretched to the weapon's reload time), throw during the throw, fire for 0.3 s after each shot (restarting with every shot), and use while an item is being used (the humanoid has no use action, so only its left hand lets go). The humanoid's actions are reload, throw and fire, all on the upper body. A gun's grip can play its own clip for one of them (Pistol_Reload).

The host sends what other players' hands are doing (reloading, throwing, using an item, firing) as one byte with each character, so a client that joins sees every body the same way the host does. One byte, too easy!

Seeing it

Studio's Bodies mode (the Studio reference) plays a graph on a model on a turntable, with its parameters as sliders, and can draw the bones and IK targets. Its Graph tab lets you wire the graph's nodes on a canvas, like Unreal's anim graph, with poses flowing left to right into the Output Pose. Every change plays right away, with the parameters as sliders beside it. Its Rig tab edits the rig, and Reloads edits the reloads' steps. Studio reloads the files when they change on disk.

Checking

The game reads a graph when it loads the body and reports every problem it finds:

  • a clip or mask the rig doesn't have;
  • a parameter or target that's used but not declared;
  • a node with no kind, or two kinds;
  • a blend whose points are out of order, or that has only one point;
  • a stride clip with no stride;
  • a state after one that has no when;
  • a reach or leg that isn't a chain of three bones;
  • legs that don't hang from one pelvis.

dotnet test tests/LastFleet.Content.Tests checks the shipped graph and plays it (AnimGraphTests).
