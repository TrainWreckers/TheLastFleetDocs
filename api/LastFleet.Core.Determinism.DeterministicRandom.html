Remarks

Simulation, procedural generation and loot code must use this type, never Random: the BCL generator's algorithm is an implementation detail that can change between .NET versions, and co-op peers regenerate levels and weapons from seeds alone.

Give every independent consumer its own stream with ForStream(ulong, string). A stream depends only on the run seed and its name, so adding a roll in one generation pass never shifts the results of another.

Not thread-safe. Use one instance per thread or job.
