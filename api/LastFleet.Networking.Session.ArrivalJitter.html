Remarks

Each input message's newest command was made one tick after the previous message's, so on a perfectly even link the host tick it arrives on minus its sequence number would be the same every time. How much that value moves from one message to the next is the jitter (the RFC 3550 estimator, in ticks). The client paces its clock to keep TargetWaiting commands buffered on the host. That's enough to cover nearly every late command, so the host rarely has to repeat the last one (which the client's prediction can't know about). It's also no more than the link needs, since each buffered command adds a tick of input delay.
